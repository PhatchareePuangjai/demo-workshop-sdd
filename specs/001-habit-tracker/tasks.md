# งานที่ต้องทำ (Tasks): Web Habit Tracker

**อินพุต**: ข้อมูลจากเอกสารออกแบบใน `/specs/001-habit-tracker/`

**องค์กร**: งานถูกจัดกลุ่มตามเรื่องราวของผู้ใช้ (User Story) เพื่อให้สามารถดำเนินการพัฒนาและทดสอบแต่ละเรื่องได้อย่างอิสระ

## รูปแบบ: `[ID] [P?] [Story] รายละเอียดงาน`

- **[P]**: สามารถทำขนานกันได้ (แก้ไขไฟล์ต่างกัน, ไม่มี dependencies)
- **[Story]**: งานนี้เป็นส่วนหนึ่งของเรื่องราวผู้ใช้ใด (เช่น [US1], [US2], [US3])
- ระบุไฟล์ที่ต้องแก้ไขในรายละเอียดงานเสมอ

---

## ระยะที่ 1: การตั้งค่า (Setup - โครงสร้างพื้นฐาน)

**วัตถุประสงค์**: เริ่มต้นโครงการและเตรียมโครงสร้างไฟล์ตามมาตรฐาน

- [ ] T001 สร้างโครงสร้างไฟล์ที่จำเป็นตามที่ระบุในรัฐธรรมนูญ (Constitution) ที่รากฐานของโปรเจกต์ (index.html, style.css, app.js)
- [ ] T002 เตรียมไฟล์ index.html พื้นฐานพร้อมลิงก์ไปยังไฟล์ CSS และ JS
- [ ] T003 [P] ตั้งค่าพื้นที่ LocalStorage สำหรับการเก็บข้อมูลนิสัยเริ่มต้น

---

## ระยะที่ 2: พื้นฐาน (Foundational - สิ่งที่ต้องมีก่อนเริ่ม)

**วัตถุประสงค์**: โครงสร้างข้อมูลพื้นฐานที่จำเป็นก่อนเริ่มทำ User Story ใดๆ

**⚠️ สำคัญมาก**: ห้ามเริ่มทำ User Story จนกว่าระยะนี้จะเสร็จสิ้น

- [ ] T004 สร้างออบเจกต์ `state` ส่วนกลางใน app.js เพื่อเก็บข้อมูลนิสัยและสถานะการทำสำเร็จ
- [ ] T005 สร้างฟังก์ชัน `render()` ใน app.js ซึ่งเป็นหน้าที่หลักในการอัปเดต DOM
- [ ] T006 สร้างฟังก์ชันจัดการ LocalStorage (saveState, loadState) ใน app.js

**Checkpoint**: โครงสร้างพื้นฐานพร้อม! เริ่มพัฒนา User Story ได้แล้ว

---

## ระยะที่ 3: User Story 1 - การสร้างและดูนิสัยประจำวัน (Priority: P1) 🎯 MVP

**เป้าหมาย**: เพิ่มนิสัยใหม่ และสลับสถานะการทำสำเร็จได้

**การทดสอบที่เป็นอิสระ**: เพิ่มนิสัยแล้วคลิกวันทำสำเร็จ และตรวจสอบว่าข้อมูลอัปเดตทั้งในหน้าจอและ LocalStorage

### การนำไปใช้ (Implementation)

- [ ] T007 [US1] สร้างฟอร์มสำหรับเพิ่มนิสัยใน index.html พร้อม ID `#item-form` และ `#form-error`
- [ ] T008 [US1] พัฒนาฟังก์ชันการเพิ่มนิสัยใน app.js (รองรับกด Enter และคลิกปุ่ม) พร้อมตรวจสอบค่าว่าง
- [ ] T009 [US1] พัฒนาตารางสำหรับแสดงรายชื่อนิสัยใน index.html พร้อม ID `#item-list`
- [ ] T010 [US1] พัฒนาฟังก์ชันแสดงรายชื่อนิสัยในตารางผ่าน `render()`
- [ ] T011 [US1] พัฒนาฟังก์ชันคลิกสลับสถานะการทำสำเร็จในแต่ละวัน และอัปเดตสถิติใน `state`

**Checkpoint**: ผู้ใช้เพิ่มนิสัยและคลิกติ๊กถูกวันได้แล้ว

---

## ระยะที่ 4: User Story 2 - สถิติเรียลไทม์และการกรอง (Priority: P2)

**เป้าหมาย**: เห็นสรุปผลรายสัปดาห์ และตัวกรองนิสัยที่ทำไม่ครบ

**การทดสอบที่เป็นอิสระ**: สร้างหลายนิสัย, ทำสำเร็จไม่เท่ากัน, แล้วลองสลับตัวกรองดูผลลัพธ์

### การนำไปใช้ (Implementation)

- [ ] T012 [US2] สร้างส่วนสรุปผลใน index.html พร้อม ID `#summary-text`
- [ ] T013 [US2] พัฒนาฟังก์ชันคำนวณและอัปเดตสรุปผลรายสัปดาห์ (สถิติรวม) ใน app.js
- [ ] T014 [US2] สร้างส่วนตัวกรองใน index.html พร้อม ID `#filter-section`
- [ ] T015 [US2] พัฒนาฟังก์ชันการกรองนิสัย (ทั้งหมด / เฉพาะที่ยังทำไม่ครบ) ใน app.js และอัปเดตตารางผ่าน `render()`

**Checkpoint**: เห็นสรุปสถิติและกรองนิสัยที่ยังไม่เสร็จได้แล้ว

---

## ระยะที่ 5: User Story 3 - จัดการนิสัย: แก้ไข, ลบ, และรีเซ็ตสัปดาห์ (Priority: P3)

**เป้าหมาย**: จัดการชื่อนิสัย และล้างข้อมูลรายสัปดาห์

**การทดสอบที่เป็นอิสระ**: แก้ไขชื่อ, ลบนิสัย, กดปุ่มรีเซ็ตแล้วข้อมูลล้าง

### การนำไปใช้ (Implementation)

- [ ] T016 [US3] พัฒนาฟังก์ชันแก้ไขชื่อนิสัยใน app.js
- [ ] T017 [US3] พัฒนาฟังก์ชันลบนิสัยพร้อมแสดงข้อความยืนยันใน app.js
- [ ] T018 [US3] สร้างปุ่ม "รีเซ็ตสัปดาห์ใหม่" ใน index.html
- [ ] T019 [US3] พัฒนาฟังก์ชันการรีเซ็ตสถานะการทำสำเร็จของทุกนิสัยให้เป็น "ยังไม่ได้ทำ" ใน app.js

**Checkpoint**: จัดการนิสัยและรีเซ็ตสัปดาห์ได้ตามต้องการ

---

## ระยะที่ 6: การเก็บรายละเอียด (Polish & Cross-Cutting Concerns)

**วัตถุประสงค์**: งานเก็บรายละเอียดและปรับปรุงให้สมบูรณ์

- [ ] T020 [P] ปรับแต่ง CSS ใน style.css เพื่อการแสดงผล Responsive และรองรับการเลื่อนแนวนอน
- [ ] T021 [P] ใส่การเน้นวันปัจจุบันด้วย CSS ใน style.css (ใช้ JS ระบุคลาส today-highlight)
- [ ] T022 [P] ตรวจสอบกรณีที่ไม่มีนิสัย แล้วแสดงกล่อง `#empty-state` ให้ถูกต้อง
- [ ] T023 [P] ปรับปรุง UI การแสดงชื่อนิสัยที่ยาวเกินไปให้เหมาะสม
- [ ] T024 ตรวจสอบความถูกต้องของการใช้งาน LocalStorage และความลื่นไหลของแอป

## การพึ่งพากันและการดำเนินการ (Dependencies & Execution Order)

### ลำดับการทำ (Phase Order)
1. **ระยะที่ 1 (Setup)**: ต้องทำก่อนเป็นอันดับแรก
2. **ระยะที่ 2 (Foundational)**: ต้องเสร็จก่อนเริ่มงานฟีเจอร์ User Story
3. **ระยะที่ 3, 4, 5 (User Stories)**: ทำตามลำดับความสำคัญ (P1 -> P2 -> P3)
4. **ระยะที่ 6 (Polish)**: งานเก็บรายละเอียดทำปิดท้าย

- พัฒนาต่อยอด User Story 2 และ 3 ตามลำดับ
- งานที่ทำขนานกันได้ (ทำเครื่องหมาย [P]) ให้แบ่งคนทำพร้อมกันเพื่อความรวดเร็ว
